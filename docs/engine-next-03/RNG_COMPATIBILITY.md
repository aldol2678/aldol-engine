## Changes and contract
- Only Next runtime changes; original src/core/rng.js and save.js remain byte-identical. CountedRng retains inherited helpers (int/float/pick/shuffle/fork) and matches original FNV-1a + Mulberry32 stream; own next has getState/setState and exact MarginLife v1 snapshot {version,seed,state}. Invalid snapshot/setter is rejected before mutation. Inverse of increment modulo 2^32 is 0xdc58aa5d.
- Direct jump from seed and draw position via 32-bit modular arithmetic; no loop proportional to draws. Time O(seed length) + O(1) in draw position; entire save parse/validation is not constant in payload size.
- Deliberate boundary policy: persisted rngDraws now denotes stream position in [0, 0xffffffff], not an unbounded lifetime counter. Existing valid values 0..50,000,000 retain meaning and exact sequence. After position 0xffffffff, the next draw wraps to position zero (full RNG state cycle), and the next save remains valid. Negative, fractional, NaN, infinity and >=2^32 constructor/save inputs reject. This avoids both cap+1 invalid saves and mid-tick exhaustion. Full-period wrap changes lifetime-count semantics only after 2^32 draws; do not use this field for lifetime analytics.
- Save envelope, keys, versions, checksum algorithm and original files unchanged. Old valid v1 saves remain readable with identical stream; new positions >50M are rejected by old Next runtime, so rollback with new extended-position saves is not guaranteed. No automatic migration or storage mutation.
- Original MarginLife RNG fixture is exact P3 head dd1a91324fe4f00f7989e0efefd2a92a6c8d144f blob b8e4331bb1fcf2d1d9326b8885d80501c3f178a2. Test uses isolated temporary combined-source tree; no original branches merged.
